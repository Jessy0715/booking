# 場地借用管理系統 - Side Project 優化與後端建置企劃

## 一、 專案核心定位
為了讓 Side Project 更有亮點且避免功能過於龐雜失焦，我們建議將系統設定為一個「有明確主題」的場地借約服務。
**推薦主題：** 獨立樂團練團室預約、或 自然光攝影棚預約系統。

透過明確的主題，我們可以：
1. 設計更具風格的 UI (例如：練團室可採用深色系與螢光點綴；攝影棚可採用大地色系與極簡留白)。
2. 讓面試官或使用者一眼就能看懂系統的實際應用場景。

---

## 二、 前端介面與功能優化建議

### 1. 前台流程優化 (User 面)
* **Hero Banner (首頁視覺)：** 加入一張高質感的滿版情境圖或輪播，提升第一眼專業度。
* **預約流程整合：** 
    1. 瀏覽場地卡片 (Room Card)。
    2. 點擊進入專屬月曆 (整合 React Big Calendar)，視覺化找尋空擋時段。
    3. 點選空檔直接彈出預約表單送出。
* **個人儀表板 (My Bookings)：** 讓使用者登入後能檢視「我的預約紀錄」，包含預約狀態（審核中 / 已核准 / 已拒絕），建立完整的使用者體驗閉環。

### 2. 後台流程優化 (Admin 面)
* **訂單審核機制：** 除了現有的場地 CRUD (新增/修改/刪除) 之外，增加一個「預約審核」的獨立分頁。條列出所有使用者的申請，管理員只需點擊「核准」或「拒絕」即可互動。
* **資料視覺化 (選配)：** 如果想炫技，後台首頁可以加個簡單的圓餅圖顯示「各場地熱門度」或「本月營收」。

## 三、 後端建置建議 (新手友善版)

對於後端新手，我們採用 **Express.js + SQLite** (或直接用陣列記憶體作為初期測試)。這樣完全不用安裝龐大的資料庫系統，非常適合快速開發。

### 1. 技術選型
* **框架:** Node.js + Express.js (處理 API 請求)
* **資料庫:** 初期可用 Array 存取，進階可無痛切換 sqlite3 (輕量級檔案資料庫)
* **跨域處理:** cors 套件 (讓 Port 3000 的前端能打 API 到 3001 的後端)

### 2. API 基礎架構規劃
後端初期只需要實作以下三支核心 API 即可撐起整個系統：

#### (1) 取得場地列表
* **Method:** `GET`
* **Route:** `/api/rooms`
* **用途:** 取代前端寫死的假資料，讓 React 透過 fetch 取得場地名單並渲染畫面。

#### (2) 送出預約申請
* **Method:** `POST`
* **Route:** `/api/bookings`
* **用途:** 接收前端送來的選擇日期與場地 ID，將此筆訂單存入資料庫，狀態標註為 `pending` (審核中)。

#### (3) 取得預約紀錄 (供後台管理)
* **Method:** `GET`
* **Route:** `/api/bookings`
* **用途:** 後台「預約審核」頁面呼叫此 API 取得所有訂單。若加上參數 `?userId=xxx`，也可以用於前台的「我的預約」頁面。

3. **建立後端服務：** 在專案外層或獨立資料庫建置 Node Server，寫出第一支 `/api/rooms`。
